# Mission: Build Sarflog Mobile Responsively

## Why
Build the first Sarflog React Native/Expo application with a layout system that remains understandable and reliable across phones, tablets, foldables, rotation, and resized app windows.

## Success looks like
- Explain the difference between a device, an app window, a breakpoint, and a layout mode.
- Build screens from shared responsive rules instead of scattered magic numbers.
- Choose when a screen stays single-pane and when additional space enables a richer structure.
- Test layout boundaries and accessibility scaling while building each vertical slice.

## Constraints
- This is the user's first mobile application, so teach one concrete idea at a time with examples.
- Sarflog targets a shippable release within 75 days.
- Mobile phone flows are primary; tablets must remain usable and adaptive.
- Compact phone-sized windows remain portrait while large windows may rotate.

## Out of scope
- Reproducing desktop-web layouts inside the native app.
- Supporting arbitrary screen-specific breakpoint systems.
- Optimizing desktop-class layouts before core phone and tablet journeys work.
