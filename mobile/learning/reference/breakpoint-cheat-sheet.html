Quick reference · React Native adaptive layout

Fluid first; breakpoints only for structure

Let Flexbox, content, wrapping, and scrolling handle ordinary phone variation. Read window size only when a real alternate layout exists.

Most mobile screens need no breakpoint condition. A breakpoint is optional: use it only where available space makes a different structure useful.

Code review checklist

  • Start without a breakpoint: use Flexbox, wrapping, scrolling, and content caps.
  • When structure truly changes, use useWindowDimensions(), not cached startup dimensions.
  • Use available window space, not model names such as isTablet.
  • Keep global thresholds centralized and mirrored into Uniwind.
  • Use mobile-first base classes; add variants only when structure changes.
  • Prefer flex, wrapping, scrolling, and maximum widths before adding breakpoints.
  • If a component truly needs a local threshold, name it, document the content reason, and test it.
  • Test both sides of each boundary: 599/600 and 839/840.
