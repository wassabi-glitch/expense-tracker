# React Native Adaptive Layout Resources

## Knowledge

- [React Native: Layout with Flexbox](https://reactnative.dev/docs/flexbox)
  Primary source for the default cross-screen layout system. Use for: fluid rows, columns, growth, shrinking, wrapping, alignment, and gaps before considering breakpoints.
- [React Native: Dimensions](https://reactnative.dev/docs/dimensions)
  Primary source for reading the available application window and why `useWindowDimensions` is preferred in React components. Use for: responsive runtime implementation.
- [Android Developers: Use window size classes](https://developer.android.com/develop/ui/views/layout/use-window-size-classes)
  Primary source for the compact, medium, expanded, large, and extra-large width classes plus height classes. Use for: breakpoint vocabulary and boundary tests.
- [Android Developers: Orientation restricted on phones but not large screens](https://developer.android.com/develop/adaptive-apps/cookbook/orientation-restriction)
  Official recipe matching Sarflog's phone-portrait/tablet-adaptive policy. Use for: understanding why available width and height matter more than device labels.
- [Uniwind: Responsive breakpoints](https://docs.uniwind.dev/breakpoints)
  Official guide for mobile-first breakpoint variants and centralized custom thresholds. Use for: keeping TypeScript layout decisions and `className` variants aligned.
- [Apple Human Interface Guidelines: Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
  Primary iOS/iPadOS guidance for safe areas, adaptable content, Dynamic Type, orientation, and resizable iPad windows. Use for: platform expectations that are broader than numeric breakpoints.
